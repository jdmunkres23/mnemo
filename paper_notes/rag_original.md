**실험 및 결과:** 4가지(oepn-domain QA, Abstractive QA, Jeoperdy Qestion Generation, FEVER) 실험에서 좋은 성능을 보임. 단, 단일 테스크에서는 성능 하락했음.

눈에 띈 결과:

**한계 및 아직 못 푼 것:** 다양한 테스크에서는 성능이 좋았지만, 단일 테스크에서는 성능이 하락한점.

**다른 논문과의 연결:** 이전 논문을 잘 모르겠음. RAG의 출발점.

**내 프로젝트에 어떻게 쓸 수 있을까:** 앞으로의 RAG의 다양한 아키텍처 이해를 위해서 기초적인 RAG 파이프라인을 이해하는 것에 초점. RAG 파이프라인은 비슷하게 사용 가능.

PAPERS.md 연결 표 확인 후 내 말로 재해석:

궁금한 점
1. RAG의 중요한 장점이 재학습 없이 비파라메트릭 베모리만 교체해서 지식을 업데이트할 수 있다고 했는데, 본 논문에서 질의 인코더와 BART 생성기는 학습 대상이 아닌가? 그러면 사실상 학습 자체는 존재하는 것 같은데, 재학습이라는 게 전체 재학습을 말하는 것인지 궁금함.

대답 : 초기 학습   → 질의 인코더 + BART 같이 end-to-end 학습 (한 번)
지식 업데이트 → 문서 인덱스(비파라메트릭)만 교체, 모델 재학습 불필요
즉 "재학습 없이"는 배포 후 지식이 바뀔 때 모델 파라미터를 다시 학습하지 않아도 된다는 뜻


2. RAG의 차이점이 단일 검색 기반 아키텍처가 다양한 과제에서 강력한 성능을 낼 수 있었다고 했는데, 단일 검색 기반 아키텍처말고 다른 아키텍처는 뭐가 있는지. 

대답 : "단일 검색 기반"의 반대는 **반복 검색(multi-hop)**이다. 후속 논문들이 바로 다음의 방향으로 발전한다.

RAG (이 논문)  → 1회 검색 → 답변
Self-RAG       → 검색 필요 여부 스스로 판단 → 필요하면 재검색
FLARE, IRCoT   → 생성하다가 불확실하면 다시 검색
