**이 논문이 다루는 문제:** 언어 모델링 테스크와 LM 확률을 알 수 없어서 RAG의 평가가 정확하지 않는 문제가 있었다.

**기존 방법의 한계:** 언어 모델링 테스크와 LM 확률을 알 수 없어서 RAG의 평가가 정확하지 않는 문제가 있었다.

- introduction 마지막 문단 참조
    - 언어 모델링 테스크 : AI가 다음에 올 단어가 무엇일지 예측하는 능력을 평가하는 기본 과제
        - 역할 : 모델이 문맥을 이해하고 문법적으로 올바른 문장을 생성하는지 확인하는 기초 체력 테스트
        - 평가 지표=perplexity : 혼란도/ 모델이 다음 단어를 얼마나 확신있게 예측하는지 나타냄. 수치가 낮을 수록 잘 예측
        - 논문에서 핵심 : RAG는 단순히 단어 예측을 잘하는 것이 아니라, 검색된 문서에서 정답을 찾아내는 능력이 중요. 단어를 잘 예측한다고 해서(낮은 혼란도를 가지고 있다 해도) 반드시 질문의 정답을 잘 찾는 것은 아니기 때문에 RAG 성능을 정확하게 판단하기 어려움.
    - LM 확률 : 특정 단어나 문장이 다음에 올 것이라고 판단한 구체적인 수치
        - 용도 : 혼란도 계산을 위해 모델이 각 단어에 매긴 확률값이 필요함.
        - 논문에서 핵심 : api를 사용하는 경우 내부 확률 수치를 알 수 없음.

**한 줄 요약 (초안):** 사람 개입없이 RAG를 평가할 수 있는 평가 파이프라인을 구축했음.

**핵심 아이디어:** RAGAS는 Faithfulness, Answer Relevance, Context Relevance 3가지 지표로 RAG를 평가한다.  
사람이 만든 정답 레이블 없이도 평가 가능한 reference-free 방식 제안.

**실험 및 결과:** RAGAS를 GPT Score와 GPT Ranking과 비교한 결과 사람이 한 것과 RAGAS가 가장 비슷했다.

눈에 띈 결과: RAGAS가 대조군에 비해서 지표에서 가장 좋은 점수를 받은 것

**한계 및 아직 못 푼 것:** GPT 의존성 — 지표 계산 자체를 GPT로 하기 때문에, judge 모델이 달라지면 점수도 달라질 수 있다. 이 프로젝트처럼 Groq(비GPT 모델)로 평가하면 결과가 논문과 다를 수 있음.

## 3패스 — 구현 목표로 깊이 읽기

> 수식·알고리즘을 따라가며 재현 가능한 수준으로 읽은 후 작성

**방법론 이해:** 

1. Section 3

- faithfulness : F = 답변을 지지하는 진술 수 / 전체 진술 수
- answer relevance : AR = 잠재 질문과 원래 질문과의 유사도의 평균 (잠재 질문은 답변으로 부터 생성한 질문)
- context relevance : CR = 답변의 핵심이 되는 문장 수 / 전체 문장 수 

2. Section4 

- 평가 지표를 이용해서 LLM과 인간이 평가한 점수가 서로 얼마나 비슷한지 확인하기 위해서 데이터셋 구축

- faithfulness : gpt에게 서론 단락 conext 있이, 없이 생성 -> anotator한테 확인
- answer relevance : gpt에게 답변 관련 낮은 후보 답변 생성 후 비교
- context relevance : 관련 페이지의 정보를 가져와서 노이즈로 추가


이해가 안 된 부분: 데이터 셋을 만든 이유가 잘 납득이 가지 않음. RAGAS에서 얻어가야 할 게 무엇인지도 잘 모르겠음. 단지 평가 지표가 중요한건지, 왜 데이터셋을 만든 건지 이해가 잘 가지 않음.

**의문점 / 납득 안 되는 부분:** LLM이 평가 지표를 잘 이해하고 점수를 매길지가 관건일 것 같음.

답 : WikiEval은 RAGAS 지표 자체를 검증하기 위한 데이터 셋임.
RAGAS가 "좋은 평가 지표다" 라고 주장하려면
→ 사람이 평가한 결과와 RAGAS 점수가 비슷해야 증명됨
→ 그러려면 사람도 평가할 수 있는 데이터셋이 필요
→ 그게 WikiEval
즉, "RAGAS 점수 ≈ 사람 판단"임을 보이기 위한 근거 데이터.



**한 줄 요약 (최종):** LLM을 이용해서 정답 레이블 없이 RAG 파이프라인이 잘 작동하는지 자동으로 평가할 수 있다.
